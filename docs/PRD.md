# PRD: FinSight

## 목표
프리랜서·1인 사업자가 카드 명세서를 올리면 AI가 거래별로 사업경비와 개인지출을 갈라주어, 세무 신고 전 경비 정리에 드는 수작업을 없앤다.

## 사용자
한국의 프리랜서·1인 사업자. 카드 한두 장을 사업과 개인 용도로 섞어 쓰고, 신고철마다 명세서를 열어 경비를 수동으로 골라내는 사람.

명시적으로 타겟이 아닌 사용자:
- 일반 개인 소비자 (가계부 용도) — 뱅크샐러드·토스가 마이데이터로 무료 제공 중인 영역이다. 수동 업로드를 요구하는 우리 제품이 이길 수 없다
- 법인 재무 담당 — 다중 사용자 권한과 보안 실사가 필요해 MVP 범위 밖

## 이 제품을 지배하는 사실

**"이 결제가 미팅인가 개인 커피인가"는 규칙으로 풀리지 않는다.** 가맹점명만으로는 판단이 안 되고, 같은 가맹점이라도 건마다 다르다. 그래서 이 제품의 가치는 AI 분류 그 자체이며, **AI 호출 원가가 곧 원가 구조**다.

여기서 두 가지가 따라온다. 요금제를 무제한이 아니라 **횟수 제한**으로 잡은 이유이고, 사용자 수정을 규칙으로 학습해 다음 달 AI 호출에서 빼는 이유다. 재방문 사용자일수록 정확도가 오르고 원가가 내려간다.

## 핵심 기능

1. **파일 업로드 + 자동 컬럼 매핑** — CSV와 엑셀(.xlsx)을 받는다. 카드사마다 다른 헤더를 휴리스틱으로 추측해 날짜/가맹점/금액에 매핑하고, 사용자가 드롭다운으로 교정한다. 인코딩(EUC-KR/UTF-8), 상단 안내문, 하단 합계 행을 자동 처리한다.
2. **집계 프리뷰** — 총액·월별·상위 가맹점을 보여준다. **모든 금액 계산은 코드가 한다.** LLM 호출이 없다.
3. **거래별 경비 분류** — 각 거래를 `사업경비 / 개인지출 / 확인필요`로 분류하고 사업경비는 계정과목까지 매핑한다. 확신도를 함께 산출해 낮은 건은 "확인 필요" 섹션 상단에 노출한다. 결과는 사용자가 수정 가능한 표다.
4. **사용자 규칙 학습** — 사용자가 수정한 분류를 `user_rules`에 저장하고, 다음 분석 때 AI 호출 전에 선적용한다.
5. **대화형 Q&A (유료)** — "지난 분기 접대비 얼마 썼어?" 같은 자연어 질의. 거래내역을 프롬프트 캐시에 두고 질의만 추가한다.
6. **구독 결제** — Polar 기반.

## 요금제

| | Free | Pro |
|---|---|---|
| 업로드·집계 프리뷰 | 무제한 | 무제한 |
| 전건 경비 분류 | 월 1회 | 월 10회 |
| 대화형 Q&A | X | 월 100건 |
| 사용자 규칙 학습 | O | O |
| 히스토리 열람 | 전체 | 전체 |
| CSV 내보내기 · 인쇄 | X | O |

**횟수 제한을 쓰는 이유**: 분석 1회(300건 기준) 원가가 약 440원이고, Q&A는 질문마다 전체 내역이 컨텍스트에 들어간다. 무제한을 걸면 헤비유저 한 명이 마진을 다 먹는다. 종량제보다 예측 가능성을 택했다.

## 사용자 흐름

```
랜딩 ─┬─ [로그인] ────────────────────────▶ 대시보드 (재방문자)
      │
      └─ 파일 드롭 → 컬럼 매핑 확인 → 집계 프리뷰 + 표본 분류 20건
                                              │
                        "전체 300건을 분류하려면 Google 계정을 연결하세요"
                                              ▼
                                   Google 계정 연결 (결과 유지)
                                              ▼
                              전건 분류 → 수정 가능한 표 → 규칙 저장
                                              ▼
                                    (Q&A 시도) → Pro 결제
```

로그인 없이 업로드·집계·**표본 분류 20건**까지 진행한다. 사용자가 이미 자기 파일을 투자한 상태라 전환 저항이 가장 낮다.

**표본 20건인 이유**: "AI가 내 경비를 제대로 가르는가"는 직접 봐야 전달되는 가치라 프리뷰에 실제 분류 결과가 있어야 한다. 동시에 전건(회당 440원)을 익명에 열면 비용 남용 표면이 생긴다. 20건이면 세션당 약 30원이고, uid당 1회로 제한한다.

**프리뷰 문구는 정직해야 한다.** 나머지 건은 분류되지 않은 상태이므로, 없는 결과를 블러로 위장하지 않고 "계정을 연결하면 전체를 분류합니다"로 표기한다.

## 정책

- **세무 조언을 하지 않는다** — 거래 분류와 계정과목 매핑까지만 한다. "경비 처리 가능/불가", "한도 초과" 같은 판단은 생성하지 않는다. 분류 화면에 "최종 판단은 세무 대리인과 상의" 고지를 상시 노출한다
- **중복 업로드** — 같은 파일을 다시 올리면 감지해서 저장하지 않고 "취소 / 기존 결과 보기"를 묻는다
- **데이터 삭제** — 내 데이터 전체를 삭제할 수 있다. 단 MVP에서는 앱 데이터 삭제 + 로그아웃까지이고 계정 자체는 남으므로, **"계정 삭제"가 아니라 "내 데이터 전체 삭제"로 표기한다**
- **업로드 상한** — 10,000행. 초과 시 명확히 안내한다
- **카드번호는 저장하지 않는다.** 원본 파일도 서버로 전송되지 않는다

## MVP 제외 사항

- 마이데이터/오픈뱅킹 자동 연동 — 금융위 허가 사항. 장기 해자이나 현 단계 불가
- 세무 신고 파일 내보내기 (홈택스 연동 등)
- 영수증 이미지 OCR, PDF 명세서 파싱
- 카카오 로그인 — 구글 먼저. 검수 리드타임이 있다
- 법인·다중 사용자 워크스페이스, 권한 관리
- 이메일 리마인더·리포트 발송 ← **신고철 재방문이 핵심이라 다음 phase 1순위**
- 사용자별 커스텀 계정과목
- 모바일 앱, PWA 오프라인 지원
- 다국어 (한국어만)
- 기존 Google 계정과의 병합, 계정 자체 삭제

## 가설과 지표

| # | 가설 | 관측 지표 |
|---|---|---|
| H1 | 로그인 전에 자기 명세서를 던진다 | 랜딩 → 업로드 시작률 |
| H2 | 매핑 자동 추측 정확도가 첫 이탈을 좌우한다 | 매핑 → 분석 실행률, 수동 교정 비율 |
| H3 | **표본 20건이 계정 연결을 만든다** | 프리뷰 → 연결 완료율 |
| H4 | 분류 정확도가 결제를 만든다 | 사용자 수정 비율, 연결 → 결제율 |
| H5 | **규칙 학습이 재방문 원가를 낮춘다** ← 유닛 이코노믹스의 핵심 | 2회차 AI 호출 건수 / 전체 거래 건수 |

## 디자인

- **라이트모드 고정.** 다크모드 미지원 — 테마 분기가 없어 컴포넌트 색 검증 비용이 절반이고, 인쇄 결과가 깨끗하다
- 금융 데이터라 가독성 우선. 무채색 기반 + 포인트 컬러 1가지
- 색은 **분류 상태(사업/개인/확인필요)에만** 쓴다. 그 외에는 쓰지 않는다
- 표 중심의 고밀도 레이아웃. 차트는 보조 역할이며 주인공이 아니다
- 숫자는 tabular-nums로 정렬. 금액은 천 단위 구분자 + 원화 표기
- 은행·회계 SaaS의 신뢰감 문법. 그라디언트·글래스모피즘·과한 애니메이션 금지
- PDF 대신 인쇄용 CSS로 대응한다
